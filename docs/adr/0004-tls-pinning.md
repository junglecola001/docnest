# ADR 0004 · 自签证书 + 指纹固定

- 状态：已采纳（实现属于 M2）
- 日期：2026-11-07

## 背景

宿主在局域网内提供 HTTPS/WebSocket 服务。没有公网域名，不想让用户安装 CA，也不想引入依赖外网的 ACME。明文 HTTP 不可接受：局域网内的被动嗅探可以拿到设备令牌和文件内容。

## 决策

1. 宿主首次启动生成 ECDSA P-256 密钥对与 10 年自签 X.509 证书；私钥存入 `flutter_secure_storage`（Windows 上由凭据管理器保护）。
2. 证书指纹 = SHA-256(DER)，base64url（无填充，43 字符），写进配对二维码（`docnest://pair?...&f=…`）。
3. 客户端为每个宿主保存指纹，`HttpClient.badCertificateCallback` 只放行指纹一致的证书（`packages/../` 见计划 §4.5.8）。WebSocket 使用同一个 `HttpClient`。
4. 指纹不符时拒绝连接并提示重新配对，**绝不**自动信任新证书；这覆盖了中间人和「证书被替换」两种情况。
5. 手动输入 `IP:端口` 拿不到指纹，改用两端显示、用户比对的 6 位数字码完成首次信任；配对成功后同样记录指纹。

## 后果

- 二维码与令牌的生命周期互相独立：二维码可随时重新生成，令牌长期有效、可单独吊销。
- `docnest_protocol` 的 `PairingLink.parse` 对指纹做长度与字符集校验，防止把截断的指纹当成有效钉。
- 协议不提供「关闭校验」的开关：调试也用自签证书 + 指纹。
