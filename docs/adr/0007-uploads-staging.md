# ADR 0007 · 上传：暂存文件 + 原子重命名

- 状态：已采纳（协议层实现完成，HTTP 接线属于 M3）
- 日期：2026-11-07

## 背景

手机通过局域网把文件写进白名单文件夹。中途断网、App 被杀、电脑重启都可能发生，因此写操作必须满足：

- 断电或崩溃不会在用户文件夹里留下半截文件；
- 断线后可以从断点继续，而不是从头再传；
- 覆盖已有文件时，旧文件仍可找回；
- 目标路径必须经过 `PathGuard`，暂存位置不能跨卷。

## 决策

1. **暂存目录在目标根目录内**：`<root>/.docnest/staging/<uploadId>.part`。与目标同卷，最后一步 `rename` 才是原子的；`.docnest` 默认在扫描排除列表里（附录 B）。
2. **会话持久化**：`UploadSession`（offset、目标、重名策略、过期时间）存在宿主侧，进程重启后可继续；24 小时无活动过期，`expireStale` 删除对应 `.part`。
3. **分块写入顺序严格**：`append` 校验 `offset == session.offset`、不超过声明大小、可选的 `Chunk-SHA256` 必须在**写入之前**校验通过；失败时不推进 offset、不落盘。
4. **偏移量持久化在写入之后**：先 `appendAt` + `flush`，再保存 offset。宁可重传一个分块，也不要把没落盘的字节记成已接收。
5. **落盘与提交分离**：`complete` 只做决策（总大小、可选整体 SHA-256、重名策略 → 最终文件名），真正的重命名由注入的 `Mover` 执行。这样状态机可以纯逻辑测试，也保证任何调用方都必须显式执行「同卷原子移动」这一步。
6. **重名策略**：`rename` 生成 `报告 (1).pdf`（最多 1000 次，之后退化为时间戳后缀）；`skip` 不写文件并返回 `skipped: true`；`overwrite` 先把旧文件移入 `.docnest/trash/`（同一根目录内瞬时完成），再替换。
7. **不信任客户端文件名**：`NameSanitizer` 替换 Windows 非法字符、去掉末尾的点和空格、给保留设备名加前缀、按 UTF-16 单元截断到 255。

## 后果

- 上传失败最多残留 `.part`，由过期清理或下次启动时的 sweep 处理；用户文件夹里不会出现半截文档。
- 分块按顺序发送（并发 2 个文件、单文件内串行），偏移量管理最简单；代价是不支持乱序分块。
- `Mover` 是唯一执行重命名的地方，未来接 HTTP 时不要在 handler 里另写一份。
